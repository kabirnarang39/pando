Source control for monorepos where hundreds of agents commit at once

Pando runs commits, rebases and history on the server. Clones take milliseconds, CI reads files without checking out, and concurrent changes land without a merge queue. Plain git keeps working.

How it works

The server creates commits from the files a client changed, rebases concurrent changes that touch different files, and moves the branch with one compare-and-swap per batch. File contents are immutable and named by their BLAKE3 hash, so every cache tier can serve and verify them.

Try it on your own repository

A server on SQLite, your git history imported, and a change landed. About five minutes.

brew install kabirnarang39/tap/pando
pandod server --listen 127.0.0.1:7420 &
pando import-git ~/code/my-repo --server http://127.0.0.1:7420
pando clone http://127.0.0.1:7420 work && cd work
echo hello > hello.txt && pando commit -m "Say hello" && pando land

Built for agents, ready for a company

Agents use Pando through a built-in MCP server or the Python, TypeScript and Go SDKs. Operators get the controls they expect, and the storage they already run.

  • Single sign-onOpenID Connect with Okta, Entra ID, Google, Auth0 or Keycloak.
  • Per-directory permissionsRead and write rules per path and per branch; partial readers get scoped checkouts and history.
  • Pre-land checksRequire green CI or an approved review before anything reaches main.
  • Your infrastructureSQLite, Postgres or CockroachDB; disk, S3, GCS or Azure. Prometheus metrics, TLS, every feature behind a flag.
  • No lock-inImport from git and export back with identical trees, any time.
